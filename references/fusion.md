# Fusion 360 design and export

For repeated inspection or selected-body STL exports, use the bundled [Fusion and STL helpers](reusable-tools.md) through the existing API/script route. They enforce an explicit active-document binding and avoid changing source geometry. Native/STEP export and design edits remain separate operations.

- Build around functional dimensions, explicit parameters, sketch constraints, and readable feature history. Separate moving or assembled components. Preserve design intent when editing and document assumed dimensions and adjustable clearances.
- Bind components to the project's stable part IDs, following [part identity](efficient-iterations-and-part-identity.md#give-parts-stable-identities). Name critical origins, axes and reference frames so a main axle and an eccentric pin cannot silently share copied coordinates. Resolve legacy component bindings before changing names used by scripts.
- Fusion Design API numeric lengths use centimeters internally and angles use radians. Use explicit expressions such as `ValueInput.createByString('10 mm')` for parameters, convert point coordinates and raw numeric values correctly, and check a known dimension. The `adsk` API runs inside Fusion; ordinary external Python may not provide it. Verify the installed version's API capabilities before using unfamiliar operations.
- Export an editable native copy when possible, STEP for CAD exchange, and STL or an appropriate 3MF for slicing. STL does not carry a reliable unit declaration: choose export units, normally millimeters for the slicer, then check a known imported dimension. Choose mesh resolution for the actual curves and functional features. STEP exchange does not preserve Fusion's native feature history.

## Keep the Fusion workspace manageable

Track documents opened or created for the task. Close finished comparison, donor, import and illustration documents after their required outputs are saved; keep the current working project active. Preserve versioned files rather than accumulating open tabs. Before closing a modified task document, preserve unsaved modeling changes in a recoverable local native archive and verify that the export succeeded. Do not discard unsaved work or close unrelated user documents. If a document cannot be preserved safely, keep it open and report it.

Use the installed application's supported document API. `Document.close(False)` discards the session's unsaved changes: use it only when those changes have already been preserved or are disposable task illustrations. Verify the actual open-document list after the operation; a close request is insufficient if the document remains open. After cleanup, reactivate the working document and report how many task documents were closed and which project remains open. A timed-out operation may still be running; inspect its outputs and application state before importing another copy or retrying.
- If Fusion or its API is unavailable, provide useful instructions or a script to run in Fusion and explicitly state that it has not been executed. A script is not a native Fusion design file.

Primary references: [Autodesk API units](https://help.autodesk.com/cloudhelp/ENU/Fusion-360-API/files/Units_UM.htm) and [Autodesk STL/OBJ export units](https://help.autodesk.com/view/fusion360/ENU/?caas=caas%2Fsfdcarticles%2Fsfdcarticles%2FSTL-files-exported-from-Fusion-360-are-scaled-incorrectly.html). Check current installed API documentation when behavior depends on the version.
